# Sprint 0.3A review quarantine

`20261015010000_harden_foundation.sql` is a forward-only migration **candidate**, deliberately outside `netlify/database/migrations`. Netlify automatically applies files in that directory during previews too. Do not move this candidate there, generate another migration from the changed metadata, or deploy database changes without senior review and separate database authorization.

The immutable SQL and snapshot for `20261014193353_wise_hawkeye` remain unchanged. `db/schema.ts` contains candidate table/key metadata; SQL is authoritative for the deferred foreign keys, trigger/function ownership and grants. No new snapshot was generated: promotion must reconcile the approved SQL and Drizzle snapshot in an isolated offline generation workspace, retaining the historical snapshot byte-for-byte and checking that future diffs do not recreate candidate tables or erase SQL-only controls. Ordinary schema generation is blocked until that reconciliation.

The candidate expects separately provisioned `hourvia_runtime` (actual runtime login) and `hourvia_operations` (non-login function owner), neither owning tables, bypassing RLS, creating roles/databases, replicating, or inheriting roles. The migrator owns retained tables and must be allowed to transfer function ownership. Role creation and credentials are intentionally absent. Review existing effective and column privileges, alternate schemas/functions, PUBLIC execution, database/schema creation rights, grants to other roles, trigger disabling and role switching. The candidate revokes direct access to public tables/sequences and creation in public; these statements do not prove the rest of the live privilege graph is safe.

Only PROVISION, RENAME and REVOKE are exposed. Ownership transfer, account/session lifecycle, invitations, reinvitation and generic membership writes remain unavailable. SQL accepts the trusted backend's actor ID; it cannot cryptographically attest a human identity behind a shared credential. There is no active authentication adapter or handler. No GUC is an authentication credential. Operation context is set locally by the fixed function, never from HTTP input. A dedicated invariant role is deferred: the non-login operations role owns narrowly restricted deferred-check functions and reads unfiltered final state. RLS is absent; adding it requires proving full invariant visibility and redesigning roles where necessary.

All roots and memberships are retained, and workspace type/owner never change (including BUSINESS ownership until a reviewed transfer operation exists). Personal creation with a distinct key resolves the existing lifetime slot; archived personal slots deny. An existing-slot PROVISION audit records slot resolution, not a second workspace creation. Same-key payload conflicts deny. Replays recheck current workspace/membership access. A completed request remains indefinitely; no expiry releases its key.

See [the sprint report](../../docs/sprint-0-3a-final-report.md) for test evidence and recovery gates. The isolated harness assumes an operator has already prepared a fresh empty disposable database with the baseline and approved candidate; it neither applies nor replays migrations. It retains fixture history, so dispose of the entire authorized test database afterward rather than deleting retained rows.
